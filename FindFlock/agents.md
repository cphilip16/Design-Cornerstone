# Repository Guidelines

## Git Workflow

- Never push directly to `main` while working on a project change.
- Create a separate branch for every change, using a descriptive name such as `feature/<description>`, `fix/<description>`, or `docs/<description>`.
- Keep commits focused and use clear commit messages.
- Push the branch to the remote and open a pull request into `main`.
- All changes must be reviewed and merged through a pull request.
- Keep the branch up to date with `main` as needed, and resolve conflicts before requesting final review.
- Do not force-push shared branches or rewrite commits that others may be using.

## Collaboration

- Before starting work, check the current branch and repository status.
- Avoid committing or modifying unrelated changes made by other contributors.
- Include relevant tests, documentation updates, and validation details in the pull request.
